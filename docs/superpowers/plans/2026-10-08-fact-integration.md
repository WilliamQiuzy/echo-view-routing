# FACT integration: the official frame-action cross-attention model on frozen E1 features (implementation checks)

> 来源：项目负责人 2026-10-08 在折输出校正一轮结束后的决定（原文照录）。执行配置为
> `configs/experiments/fact_integration_v1.yaml`，在运行任何检查之前提交。

**这轮正式结束，不再扩展 T-in／T-out／P-out。下一步我建议换一个此前没有检验过的模型机制：显式学习“帧属于哪个切面段”，先接入已有论文模型验证。**

这轮的结论不只是“没有显著差异”。主评估六个差值中，五个方向为负；T-out 修好少量 A5C，却新增更多 A4C 错误，还降低了边界召回。辅助评估里，折编码器 1、2 的十二个组合中，简单 P-out 的点估计全部领先 T-out。因此，**目前没有证据表明这套训练方式带来了额外的时间建模优势。** 但也不能把原因直接归结为训练轮数或概率尺度，本轮没有区分这些因素。

我也需要纠正自己的推进方式：最近几轮一直围绕已有输出做校正，离“开发更好的模型”越来越远。接下来应该回到视觉特征，检验不同的分段建模方式。

可以把下面任务发给 Claude：

---

**下一轮先接入 FACT，完成训练集上的实现检查，不立即启动大规模比较。**

**1. 方法来源与要检验的区别。**

使用 CVPR 2024 的 **FACT（Frame-Action Cross-Attention Temporal Modeling）** 官方实现。它同时维护帧特征和片段 token，通过双向 cross-attention 交换信息，并用匹配损失监督 token 对应参考片段。[论文](https://openaccess.thecvf.com/content/CVPR2024/html/Lu_FACT_Frame-Action_Cross-Attention_Temporal_Modeling_for_Efficient_Action_Segmentation_CVPR_2024_paper.html)

我们要检验的区别是：**在训练中直接学习片段与帧的对应关系，能否改善短段保留、类别判断和误切之间的权衡。** 之前 M5 的输出池化、ASRF 的边界细化和 Q0/Q1 的候选删留，都没有完成这个检验。

这是一个待验证的机制，不代表已经发现了有效的新方法。FACT 是前人的模型，接入成功也不能称为我们的创新。

**2. 固定输入，回到强视觉表征。**

使用冻结的 **E1 512 维逐帧特征**，保留当前 224×224 输入和正确时间顺序。此次不使用 B0 的五类概率，不混合三个折编码器的特征，不微调视觉编码器。

后续正式比较应是 **同一份 E1 特征上的 FACT 与 ASRF**，再与 B3 和历史最强配置比较。当前先完成接入。

**3. 使用官方无 transcript 模式。**

固定官方代码提交，采用 `FACT.trans=false`。训练时可以从参考标签得到片段用于损失；**推理时不能提供真实类别顺序、真实段数或边界。**

使用一对一片段匹配。token 数量只根据训练集最大参考段数确定，不读取开发集来设置。官方仓库提供了自定义数据及 token 数量的配置说明。[官方代码与数据指南](https://github.com/ZijiaLewisLu/CVPR2024-FACT/blob/main/DATASET_SETUP_GUIDE.md)

**4. 先完成四项检查。**

- 冻结特征、帧索引、参考标签和来源记录逐项对齐。
- 覆盖单切面录像、同切面拼接、A4C→A5C→A4C，以及同类重复出现的不同片段。
- **推理标签隔离检查：** 固定输入，替换传入的参考标签，预测必须不变。官方接口仍接收标签参数，需要实际验证。
- 在固定的 16 条训练序列上做小样本过拟合检查，确认分类、匹配和帧段对应的梯度路径正常。它只验证实现，不作为泛化结果。

**5. 本阶段交付。**

给出实际 token 流程图、官方结构与适配改动、损失定义、检查结果、参数量及实测训练成本。随后写出 FACT／ASRF 的配对训练配置，明确训练预算、选点规则和比较指标。

本阶段不读取开发集指标，不启动正式多种子训练，不追加自创模块。test 继续封存。

---

**下一步的重点是“训练中显式建模片段”，不是单纯把 self-attention 换成 cross-attention。** 我查过当前项目记录，没有看到这类片段 token 匹配模型的有效实验；它值得先做实现验证，但是否能超过强基线仍然未知。

## 执行时固定的实现选择（配置中逐条记录）

- **官方代码。** `ZijiaLewisLu/CVPR2024-FACT`，固定提交 `7bd81bda2b84618a3e23876a2637a82f24881122`，克隆在服务器的
  `third_party/fact`（本地测试另克隆同一提交），从不修改。官方依赖 yacs 固定为 0.1.8，以 `--no-deps` 装入项目 `.venv`，其他包不变。
  服务器的 torch 2.14 下，`Dropout2d` 对三维输入仍按通道丢弃，与官方使用的 torch 1.12 一致，所以不需要补丁。
- **适配器。** `echo_routing/temporal/fact_head.py` 原样导入官方的 `FACT` 模型、`MatchCriterion`、`compute_null_weight` 和配置默认值，
  只负责数据接口。官方包按包名导入，不加入 `sys.path`。
- **基础配置。** 用官方指南示例中的 `breakfast.yaml`（4 个块 `iuUU`、512 维、MS-TCN++ 帧分支）。指南提示小数据集可用 `gtea.yaml`。
  本阶段只报告 `gtea.yaml` 的参数量和成本，不训练，也不据此选择。
- **数据集字段（按 `utils/gen_config.py`）。**
  - `trans=false`，一对一匹配，`token_ratio` 取默认 1.5。
  - token 数为 int(1.5 × 训练集最长 transcript)。transcript 是序列的标签段数，同切面拼接算一段。训练库最长 8 段，所以 token 数为 12。
  - 平均 transcript 长度按一个 epoch 的训练序列计算：1,500 条构造流各一次，加 1,500 个各为一段的原生窗口，结果为 2.654。
  - 没有背景类，不传类别权重，null 类权重按官方公式计算。
- **训练数据。** 与 ASRF 相同的共享批次（`TrainData.epoch_batches`，每次更新 4 条构造流加 4 个原生窗口）。每条序列去掉填充后逐条送入官方
  forward，损失为官方的逐视频平均。
- **推理。** 传入全零的假标签，从不传参考标签。
- **四项检查。**
  - **对齐。** 训练库每条流的片段、特征、帧索引、标签、拼接位置和来源录像，都与直接读取的缓存文件逐项核对；每个训练录像都核对；
    种子 0 第 0 个 epoch 的原生窗口和全部 375 个批次在去填充后与原序列核对；官方的 transcript 解析与我们的分段核对。
  - **覆盖。** 统计各类情形的条数，并按固定规则抽 16 条序列。规则是：五个类别各取协议顺序中第一个训练录像的前 256 个样本；
    再按训练库顺序、不重复地取三条含同切面拼接的流、三条含 A4C→A5C→A4C 的流、三条其他含同类重复片段的流，以及两条段数最多的流。
  - **推理标签隔离。** 检查 16 条序列和训练库前 200 条流，用初始模型和过拟合后的模型各做一次。对官方 forward 依次传入参考标签、
    全零、随机、时间反转和单个样本五种标签。预测标签和最后一块的 logits 必须完全相同。另核对适配器的假标签解码与此一致。
  - **过拟合。** 16 条序列分成两个固定批次交替训练 1,000 次更新，用 AdamW（3e-4，权重衰减 1e-4，梯度裁剪 1.0，学习率不变），
    官方的通道遮挡和时间遮挡保持开启，种子 0。每 50 次更新记录各项损失（帧分类、token 分类、两个方向的 cross-attention、
    分段、平滑）。最后报告帧准确率、段 F1@50、transcript 是否完全一致、匹配是否一对一、匹配 token 的类别是否正确，以及未匹配
    token 是否预测为 null。
  - **梯度路径。** 初始化时在第一个过拟合批次上让每项损失单独反传，按参数组列出有无梯度。官方总损失的零梯度参数在初始化时和
    过拟合后各列一次。
- **成本。** 用种子 0 第 0 个 epoch 的批次，预热 5 次后计时 100 次更新，记录每次更新的秒数和显存峰值，设置与计划中的训练相同
  （fp32、TF32 关、cuDNN 确定性）。ASRF（输入 512 维）在同一批次上同样计时。
- **输出。** 仓库只存计数和摘要：`docs/results/2026-10-08_fact_integration/` 中的 `data_checks.json`、`model_checks.json`、
  `overfit_curves.png` 和英文 README。序列 id 留在服务器的 `runs/fact_integration_v1/`。
- **不做的事。** 不读取开发集的特征、标签或指标；不读取 test；不读取 EchoNet-Pediatric；不启动正式多种子训练；不加自创模块。
- **配对训练配置。** 在检查完成后写出，作为下一阶段的待定配置，本阶段不运行。
