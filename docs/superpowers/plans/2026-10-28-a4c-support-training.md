# A45: class-specific A4C support verification implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Codex directly owns execution; one advisory read-only plan reviewer, no Claude worker or competing queue.

**Goal:** Test whether an independently trained A4C visual-support model can veto harmful frozen A44 A5C proposals while preserving real recovery and complete segmentation.

**Architecture:** Freeze the original A08 representation and A44 source0 C/N proposals. Train denoising reconstruction models on deployed-unit512-d run embeddings: A learns only correct-A4C support, U learns nonspecific balanced A4C/A5C support. Independent inner-session calibration fixes an out-of-A4C-support threshold for each; only an existing positive A5C proposal AND outlier evidence can edit an original Base-A4C run. This is a one-class generative verification problem with separately calibrated abstention, not another C/N classification-loss coefficient or a claim of new anatomical evidence.

**Tech Stack:** Existing A31 immutable feature/output/P-run caches, PyTorch FP32 CPU, NumPy, original full-sequence evaluator. No pixel inference or GPU training needed; cached features are the intended frozen-input model, not a substitute for promised encoder adaptation.
