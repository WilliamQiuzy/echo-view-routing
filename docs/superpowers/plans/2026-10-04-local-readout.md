# 第七轮：冻结 E1 的全局与局部读取对照 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 预注册配置：`configs/experiments/local_readout_v1.yaml`，在任何训练之前写定并提交。

**Goal:** 检验一个尚未验证的假设：冻结的 E1 编码器的局部 patch 特征中，是否存在全局向量不容易读出的 A4C/A5C 区分信息。这不是已发现的缺陷——ViT 本身已经处理了局部区域，我们只是尚未比较不同的读取方式。主要比较是 P2−P1。

**决定来源：** 项目负责人 2026-10-04（CETUS 验收之后）。CETUS 不加入训练；test 继续封存；论文继续暂停。注意力多实例学习（Ilse 等，ICML 2018）是成熟方法，本身不算创新；本轮只判断是否找到了一个可改进的具体瓶颈。

**Architecture:**
- P0：全局向量按时间取平均，就是第六轮 V0，必须逐序列复现其验证预测。
- P1：每帧的全局 token，经残差帧模块，再做可学习的时间加权（门控注意力），接同一个区间分类头。
- P2：每帧的 197 个 token（全局 token 加 196 个 patch token），先用门控注意力读取局部区域，再用与 P1 相同的时间加权和分类头。P2 能关注全局 token，但没有 P1 的残差帧模块，所以这是参数量匹配的两种读取方式的比较，不是 P2 能复现 P1 全部功能的嵌套检验（2026-10-04 结果后收窄的表述）。
- 同层同维：都取最后一个 block 的输出，经 ln_post 和 proj 到 512 维。P1 的残差帧模块与 P2 的 token 注意力参数量相同（131,712 对 131,457），总参数 329,091 对 328,836。
- 数据、帧、标签、权重、种子、优化器、批次和预算全部沿用第六轮：第六轮冻结的 ASRF 候选区间，每区间最多 32 帧，8 个 epoch，取最终权重，不用验证数据做任何选择。

- 独立代码审查确认 P1/P2 公平（同一次前向、同样批次、同样调度和裁剪、时间模块和分类头初始化相同），P0 走的就是第六轮 V0 的函数。

**结果（2026-10-04，`docs/results/2026-10-04_local_readout/README.md`）。** 启动条件三个种子全部满足（P0 逐序列复现 V0；token 0 差 9.5e-7；参数量与配置一致）。按预注册规则：P2 相对 P1 没有分类收益，也没有系统收益，**这条局部读取路线结束**：这种 patch token 读取方式没有带来一致的性能收益。这是操作上的停止决定，不能证明这些 token 不含额外的 A4C/A5C 信息（2026-10-04 收窄）。
- P2−P1：两个半区的准确率、两类召回、区分度和 segment F1@50 都没有一致差异；区分度在六个种子-半区格里都略低（0.3–0.7 个 AUC 点），区间都含 0。P2 与 P1 之间没有 A5C 单元被纠正，也没有 A4C 单元被弄错。
- 附带观察（不是本轮问题）：P1 的组合读取比 P0 的简单平均排序更好，在 calibration 上一致提高区分度（+1.2 到 +3.4 个 AUC 点），但在固定阈值 0.5 下没有转化为准确率或分段收益。P1 同时加了残差帧模块和参数，所以不能单独归因于时间加权。
- 三组在 selection 上都一致低于 ASRF 默认输出和最强旧配置；没有任何组达到最终目标；改用 0.9739 作参照也不改变结论。selection 上"A5C 判成 A4C"的错误在每组每个种子都来自同样 4 段录像，ASRF 自己的投票也错在这 4 段上。

## Task 4 — 不训练的阈值检查（项目负责人 2026-10-04 结果后决定）

- [x] 预注册 `configs/experiments/threshold_check_v1.yaml`（33ce14b，评估任何阈值之前）：冻结全部权重、候选区间和合并规则，只用已保存的 P0、P1 分数；网格 0.05–0.95；只在 calibration 半区按"native F1 ≥0.980、边界召回 ≥0.95，再最大化 segment F1@50"选阈值，平局取最接近 0.5、再取高于 0.5 的；无可行阈值即报告失败，不换回退规则；选定后只在 selection 半区应用一次。
- [x] 结果（`docs/results/2026-10-04_local_readout/threshold_check/README.md`）：**没有收益**，按规则结束对这批固定区间和读出分数的继续搜索。
  - 每组每个种子都有可行阈值，但选出的阈值在种子间来回摆动（P0：0.35/0.65/0.60；P1：0.65/0.35/0.75）；在 calibration 上只多 0.1–0.9 个点（乐观）。
  - selection 半区相对 0.5：P0 +1.8/−0.5/−0.4，P1 −0.3/+0.1/−0.3，没有一致差异；两组都校准后 P1−P0 为 −2.0/+0.1/−0.3（种子 0 区间在 0 以下），P1 的排序改善没有变成更好的决策。两组都一致低于最强旧配置，没有达到最终目标。
  - 阈值改变的 63 个 A5C 区间判定中有 61 个来自那 4 段共同录像；改变的 43 个 A4C 区间判定都不在这 4 段里。调阈值只是在这 4 段录像的 A5C 和其他录像的 A4C 之间交换错误。这 4 段录像的约 40 个错误片段是重复使用的素材，不是 40 个独立病例，既不能证明标签错误，也不能证明视觉信息不足。
