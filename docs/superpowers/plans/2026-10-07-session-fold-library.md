# Session-fold prediction library: predictions from encoders that did not train on the recordings' sessions

> 来源：项目负责人 2026-10-07 在 A4C/A5C 类别对阈值检查结束后的决定（原文照录）。执行配置为
> `configs/experiments/session_fold_library_v1.yaml`，在写出折划分和训练任何模型之前提交；折的组成（只含计数）在训练之前提交。

**这轮同意结束：不再调 Q0/Q1 的阈值，也不接入完整系统。下一步我建议改变训练错误样本的生成方式，先做一次按 session 留出的基线训练。**

我核对了报告和原候选库配置。有两个问题需要分开：

- **当前阈值确实不好用。** 保住正确段后，错误段大量留下。
- **还不能证明这些段无法区分。** 校准只有 11–14 个正确候选，“保留 95%”实际变成了“必须保住最低分的那一个”。这个任务设计不足以回答原先的问题，这部分是我之前规划得不够好。

另一个限制更根本：**原候选库虽然按 session 划分，但生成特征和概率的 L1 已经训练过全部这些录像。** 因此，判别器学习的错误分布，可能与模型面对新录像时的错误不同。我们尚未证明这就是失败原因，但继续在同一候选库上换模块，很难把它排除。

下面这段可以直接交给 Claude。

---

**下一轮任务：建立编码器未训练过对应录像的预测库，为后续错误修正训练提供依据。**

**1. 本轮只回答一个问题。**

当生成预测的视觉模型没有训练过对应 session 时，训练库中能否得到足够分散的 A4C/A5C 错误，以及真正需要保留的短段？

这次会训练现有基线。暂不训练新的段级判别器，不把建库本身称为模型贡献。

**2. 只使用 EV9V 原训练集，按 session 做三折。**

先划分 session，再生成窗口和构造流。同一 session 的所有录像必须在同一折。尽量平衡五类录像及 A4C/A5C 来源 session 的数量，划分规则事先固定。

每次用两折训练，预测剩下一折。最终每段录像都有一份来自“没有用这个 session 训练过”的模型预测。原 calibration、selection 和 test 都不参与本轮训练、选点或评估。这里仍是 session 留出，不能称为患者留出。

**3. 训练三个现有 B0 模型，不引入新结构。**

使用项目已有的 **ResNet-18＋五类分类头，从 ImageNet 初始化**。我已核实[现有实现支持这个初始化](/Users/williamqiu/Desktop/Harvard/Capstone/echo-view-routing/echo_routing/features/encoder.py:15)。

每折一个模型，先用一个固定种子。沿用 B0 v3 的学习率、批大小、类别权重和采样方式，固定训练 30 epoch，取最后权重。关闭依赖原验证集的早停和选点。保留当前有效的 **224×224 输入流程和正确时间顺序**。

不能从现有 B0、E1 或 L1 权重继续训练，再把留出折称为编码器未见数据。三个折也是三个不同训练集，不能当作三个重复种子。

**4. 先看识别错误，再生成短段候选。**

先报告五类识别结果，重点列出 A4C→A5C、A5C→A4C 的错误数、来源录像数和 session 数。保留全部公开标签，不根据预测筛除困难录像。

随后在每个留出折内部构造流，沿用固定 J0、κ=8 生成候选，不重新搜索解码参数。控制以下问题：

- 原生录像与构造流采用对称的对比度处理，避免增强方式提示候选类别。
- 保留同切面拼接作为对照。
- 单独报告 A4C/A5C，不能让其他容易类别撑起总体指标。
- 重复拼接和数据增强不计作新增独立病例。

这些仍是构造流，不能解释为真实连续扫查。

**5. 本轮交付两张核心表，不继续调阈值。**

第一张：各折五类识别，以及 A4C/A5C 错误涉及多少录像和 session。

第二张：正确短段、错误碎片和无法归入二分类的候选，各有多少；分别来自多少录像和 session；长度、置信度、拼接位置有什么差别。

保存逐帧概率、来源映射和模型版本。不同折的视觉特征分别保存，暂不假设三个模型的特征坐标可以直接混合训练。

**6. 本轮结束后再决定训练什么。**

如果关键错误分散在足够多的来源录像上，下一步才设计“用未见录像预测训练错误修正器”的对照，并提前评估校准样本量是否支持所要求的保留率。

如果仍只有少数来源录像，或正确段与错误段主要靠拼接来源就能区分，就明确报告这个限制。增加拼接数量不能解决它，也不因此追加更复杂的模型。

---

**这一步不是承诺能超过 B3 或 ASRF。它要先解决一个尚未处理的训练问题：让后续模块学习模型面对未见 session 时产生的错误。** 当前强基线目标保持不变，论文继续暂停。

## 执行时固定的实现选择（配置中逐条记录）

- 数据：协议的 3,364 个训练录像（502 个 session），按清单核对都属于原训练集。验证两个半区和 test 不读取。
- 折划分：scikit-learn `StratifiedGroupKFold(n_splits=3, shuffle=True, random_state=20261008)`，录像按 id 排序，y 为五类标签，组为 session。在任何预测出现之前，只按录像组成比较了几种规则；这一种让五类录像数在各折之间相差不超过 1.4%，A4C、A5C 来源 session 数分别相差不超过 2 和 3。折的组成（只含计数）在训练前提交。
- 训练：`echo_routing.features.train_encoder.train_fixed_epochs`，与 B0 的 `train` 用同一套采样、类别权重、优化器、余弦学习率、bf16 和 gamma 增强，输入为 224 letterbox、按数字顺序读帧。不读取任何验证数据，没有早停，也不选点；固定 30 epoch，保留最后一个 epoch 的权重。三个折用同一种子 0，从 ImageNet 初始化。
- 预测：模型 k 对折 k 的全部录像按 10 Hz 预测（orig 与 gamma090 两种对比度），概率、logit 和 512 维特征写入以模型 k 的检查点哈希为键的特征缓存。每个模型一个缓存，互不混用。
- 表一：每折及合并的逐样本和逐录像（逐样本 argmax 的多数投票，平票取较小类别号）五类识别；A4C→A5C 与 A5C→A4C 的错误样本数、出现错误的录像数和 session 数，以及投票判错的录像数和 session 数。
- 构造流：在每个留出折内部，用 `make_multi_recipes`（4–8 个片段、每段 10–40 个样本、同切面拼接概率 0.35、不同流之间可以重复使用录像、同一流内不重复），每折 500 条。
- 对称的对比度处理：构造流的每个片段和每个原生录像都以 0.5 的概率使用 gamma090，否则用 orig。原生录像的抽取有固定种子。
- 候选：固定 J0（λ = 0、κ = 8）解码，X → Y → X 模式，类别规则与短段探针相同，连接类型按已核实的同切面或切面变化区分。
- 表二：每折及合并，所有类别对、A4C/A5C 与其他类别对分开；(a)(b)(c) 各自的数量、录像数、session 数、来源（原生或构造流）、连接类型、对比度、中间段长度与置信度的四分位数，以及集中程度（最大单个录像占比、有效录像数）；(c) 的原因。
- 保存：特征缓存（逐样本概率与特征）、每个 session 的折、构造流与候选列表（含 id，只留在服务器）、模型版本（检查点 sha256、缓存键、训练日志）。三个模型训练和核对后用 `scripts/freeze_model.py` 冻结。
- 本轮不设判定规则；两张表交给负责人决定下一步。
