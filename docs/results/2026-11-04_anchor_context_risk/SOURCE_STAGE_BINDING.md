# Logical source phase and actual supervisor label

The sole authorized teacher process was launched under actual supervisor stage `producer`; the already-frozen producer code records the logical phase as `source_production_stage="sources"`. This is an administrative label difference. The active84 source objects, raw process ledger and produced manifest remain unchanged. The process is not restarted and no forward is repeated to change a name. Resource totals already charge the actual `producer` job's entire occupied wall once.

After actual source completion, `bind_event_risk_source_stage.py` creates a new immutable `source_stage_binding.json` from the original manifest, producer identity and every public `process_producer_*.json` receipt. It binds logical `sources` to actual `producer`, exact manifest/identity SHA and producer Git, all eight source records (input identities/journals/units/prefix history), and original attempt receipt IDs/host/PID/start/wall/CPU/GPU/OS fields plus raw-file SHA pins. Unknown or failed attempt statuses are retained. The source-cost consumer recomputes this entire binding, verifies each raw receipt against the authoritative ledger and rejects duplicate/split accounting. There is no unproved fallback from `sources` to `producer`.

The future package actual-Git freeze must explicitly add this new binding as an input (`--input docs/results/2026-11-04_anchor_context_risk/source_stage_binding.json`). Package validates that frozen input before rendering or exporting, and its cost report keeps logical and actual names separate. Multiple/failed/resumed attempts retain unknown actual forward totals under the existing rule; their CPU/GPU attempts are still summed once. This changes no source model, recipe, prediction, event feature, optimizer, threshold, endpoint, resource cap or deadline. The binder is a local aggregate-only administrative operation after actual source evidence arrives, not a new source stage or A63.
